# 媒介助手 MVP 产品需求文档（PRD）

> 版本：v1.1  
> 日期：2026-08-17  
> 产品阶段：验证型 MVP  
> 目标周期：7 天  
> 文档状态：已确认，进入原型与技术验证  
> 适用平台：首版仅支持小红书

## 1. 文档说明

本文档定义媒介助手 MVP 的产品目标、范围、业务流程、功能规则、数据模型、AI 处理方式、异常状态和验收标准，作为原型设计、技术方案、Vibe Coding 和测试验收的共同依据。

本文档中的内容分为三类：

- **已确认需求**：产品范围和业务规则已经由产品决策者确认。
- **待验证假设**：必须通过技术验证、用户测试或本地 Eval 才能确认。
- **外部约束**：受小红书平台机制、法律法规或第三方服务影响，产品无法单方面保证。

本产品提供达人筛选和广告内容辅助审核，不替代平台授权、人工判断、律师意见或监管机关认定。

## 2. 项目背景

### 2.1 目标用户

需要寻找素人进行推广的小红书媒介专员。目标达人通常约 1,000 粉丝，部分达人虽达到一定粉丝规模，但未入驻蒲公英，因此无法通过蒲公英完成标准化检索。

### 2.2 当前流程

媒介专员根据产品相关关键词在小红书搜索，再逐个进入博主主页，检查粉丝量、活跃度、历史内容、项目经历和用户特征。小红书站内搜索缺少满足该场景的组合筛选能力，导致筛选耗时且结果依赖个人经验。

内容进入发布前，媒介专员还需要根据广告法、平台规则、行业规范及公司规则审核达人图文。规则分散、更新频率不同，人工审核容易遗漏且难以溯源。

### 2.3 核心问题

如何让媒介专员通过一句自然语言要求，更快找到未入驻蒲公英的合适小红书素人，并对待发布的图文内容完成可溯源的辅助审核？

## 3. 产品目标与成功标准

### 3.1 产品目标

在 7 天内完成一个可运行的验证型 MVP，贯通以下闭环：

```text
注册/登录
→ 创建推广项目
→ 输入自然语言筛选要求
→ 首次开始检索时检查小红书会话，无有效会话则扫码连接
→ 实时获取并筛选达人
→ 管理选入/弃用结果
→ 上传图文进行内容审核
→ 展示风险依据与修改建议
```

### 3.2 成功指标

| 指标 | 目标 | 验证方式 | 当前状态 |
|---|---:|---|---|
| 找人任务效率 | 15 分钟内找到 20 名可用候选人 | 人工计时对照测试 | 待验证 |
| 达人筛选人工准确率 | ≥ 70% | 本地标注集 Eval | 待验证 |
| 内容审核风险召回率 | ≥ 80% | 本地标注集 Eval | 待验证 |
| 默认候选数量 | 每批 20 人 | 功能验收 | 已确认 |
| 项目内重复达人 | 0 | 数据唯一性测试 | 已确认 |

准确率和召回率不得在完成真实 Eval 前对外宣称为已实现结果。

## 4. 产品范围

### 4.1 MVP 包含

- 个人账号注册、登录和退出。
- 多个人账号之间的数据隔离。
- 用户首次检索或会话过期时扫码连接自己的小红书账号，有效期内复用会话。
- 推广项目创建、编辑和归档。
- 自然语言达人筛选条件输入与结构化解析。
- 扫码登录后实时获取小红书候选数据。
- 硬条件筛选、内容语义匹配、排序和匹配理由。
- 达人列表、主页跳转、选入、弃用、状态互转。
- 项目内达人去重、自定义标签或分组。
- 达人列表导出 Excel。
- 单篇小红书图文内容审核。
- 图片 OCR、标题和正文审核。
- 只读公共《中华人民共和国广告法》知识库。
- 用户创建多个私有知识库并上传自有规则。
- 审核风险定位、规则依据、风险等级和修改建议。
- 审核历史记录。

### 4.2 MVP 不包含

- 小红书以外的平台。
- 蒲公英账户和投放订单管理。
- 自动联系达人、议价、下单或发布内容。
- 视频内容审核。
- 图片中非文字视觉违规识别。
- 企业组织、团队空间、成员邀请和角色权限。
- 复杂数据看板。
- 对外开放的 Eval、token 或费用页面。
- 线上部署 Eval 数据、Eval Runner 和测试报告。
- 商用级并发、灾备、服务等级承诺。

## 5. 用户与账号体系

### 5.1 用户角色

MVP 只有“个人用户”一种角色。系统支持多个个人账号，但账号之间不能共享数据。

### 5.2 登录方式

优先采用成熟认证服务提供的邮箱验证码或魔法链接。若第三方邮件服务影响 7 天进度，可以采用邮箱和密码，但必须使用成熟认证库或托管认证，不自行设计密码加密协议。

### 5.3 数据归属

所有用户业务数据必须绑定系统生成的 `user_id`，包括：

- 小红书连接会话
- 推广项目和检索任务
- 项目达人及状态
- 自定义标签和分组
- 私有知识库及文档
- 内容审核任务和审核结果

后端必须从已验证的登录凭证获取当前 `user_id`，不得信任前端自行提交的 `user_id`。

### 5.4 小红书连接与系统登录的区别

- 媒介助手账号用于识别产品用户和绑定业务数据。
- 小红书扫码用于连接该用户自己的小红书会话。
- 两者是独立身份，不得相互替代。
- 登录媒介助手后直接进入工作台，不强制先扫码；仅在用户开始达人检索且没有有效小红书会话时触发扫码。
- 小红书会话有效期内，用户后续检索或重新登录媒介助手均不重复要求扫码；会话过期、失效或受限时再提示补扫。
- 小红书密码、验证码、Cookie 和 Token 不得要求用户以文本方式上传。

## 7. 核心用户流程

### 7.1 达人检索流程

```text
用户登录
→ 创建或进入推广项目
→ 输入筛选要求
→ 系统解析条件并展示
→ 用户确认/修改条件
→ 用户点击开始检索，系统验证小红书会话
→ 无有效会话时扫码，成功后自动继续本次检索
→ 系统实时搜索和采集候选
→ 硬条件过滤及项目内去重
→ AI 分析内容并排序
→ 展示候选达人和匹配依据
→ 用户选入、弃用或保留待处理
→ 分组、标记或导出
```

### 7.2 内容审核流程

```text
用户登录
→ 进入新建审核
→ 上传图文图片并输入标题、正文
→ 输入审核要求或推广脚本（可选）
→ 选择一个或多个私有知识库（可选）
→ 系统执行 OCR
→ 广告法与私有规则分别检索
→ AI 生成结构化风险结果
→ 用户查看风险定位、依据和建议
→ 保存审核记录
```

## 8. 功能需求

### 8.1 FR-01 账号注册与登录

**用户故事**：作为媒介专员，我希望拥有独立账号，以便保存自己的项目、达人结果和私有规则。

**功能规则**：

- 用户可注册、登录和退出。
- 邮箱必须唯一。
- 未登录用户不能访问业务页面。
- 登录过期后，引导重新登录；不得丢失已经成功保存的数据。
- 所有业务查询默认按当前 `user_id` 过滤。

**验收标准**：

- 两个账号互相无法查询对方项目、达人、审核记录和私有知识库。
- 修改 URL 或请求参数不能越权读取其他账号数据。

### 8.2 FR-02 小红书扫码连接

**用户故事**：作为媒介专员，我希望扫码连接自己的小红书账号，以便系统获取实时候选数据。

**功能规则**：

- 登录媒介助手后不主动要求扫码，用户可直接进入工作台和非达人检索模块。
- 用户首次点击“开始检索”时，后端必须先验证当前 `user_id` 绑定的小红书会话。
- 会话有效时直接继续检索，不展示二维码或重复要求扫码。
- 会话不存在、过期或失效时展示二维码；扫码成功后自动恢复用户刚才发起的检索。
- 页面展示二维码、连接状态和操作说明。
- 状态至少包括：未连接、等待扫码、等待确认、已连接、已过期、连接失败、账号受限。
- 已连接状态显示小红书账号的脱敏标识和最后验证时间。
- 会话必须与当前 `user_id` 绑定，并加密存储或使用受保护的会话存储。
- 用户可主动断开连接。
- 采集过程中若会话过期，任务暂停并提示重新扫码。

**外部约束**：

扫码登录不等于取得批量采集、长期存储或商业使用平台数据的许可。技术方案必须单独验证平台规则、稳定性、频控、账号安全和数据处理边界。

**验收标准**：

- 用户扫码后能看到明确连接状态。
- 用户登录媒介助手后可直接进入工作台；首次检索才触发扫码。
- 同一有效小红书会话内重复检索以及重新登录媒介助手均不重复扫码。
- 会话过期后再次开始检索会要求补扫，成功后继续原任务。
- 连接过期不会静默返回空结果。
- 不记录明文密码、验证码或可直接暴露的会话凭证。

### 8.3 FR-03 推广项目管理

**用户故事**：作为媒介专员，我希望按推广产品建立项目，以便隔离不同推广任务的检索条件和达人结果。

**字段**：

- 项目名称：必填，1–50 字。
- 推广产品：选填，1–100 字。
- 项目说明：选填，最多 1,000 字。
- 项目状态：进行中、已归档。
- 创建时间、更新时间。

**功能规则**：

- 用户可创建、编辑项目。
- 归档项目不可发起新检索，已有数据仍可查看和导出。
- 一个项目可执行多次检索。
- 不同项目允许保存同一达人。

### 8.4 FR-04 自然语言筛选规则解析

**用户故事**：作为媒介专员，我希望用一句话描述达人要求，不必手工配置大量筛选项。

**输入示例**：

> 粉丝小于 1500，活跃度较高，做过光子嫩肤、水光针、皮秒、点阵、超声炮、热玛吉或针清，或者有晒斑、雀斑、黄褐斑、产后斑困扰。

**解析类别**：

- 硬条件：可通过结构化字段直接判断，如粉丝数上限。
- 语义条件：需分析历史内容，如做过的项目、皮肤困扰。
- 偏好条件：用于排序而非强制排除，如“活跃度较高”。
- 返回数量：顶部“开始检索”每次创建一批，目标最多新增 20 人；再次点击时从持久化游标获取下一批。

**功能规则**：

- 系统先展示解析后的条件，再开始检索。
- 用户可以修改、删除或补充解析条件。
- 不支持或含义模糊的要求必须标记，不得擅自解释后直接执行。
- 每次检索保存原始输入和解析后的结构化条件。

**建议结构化输出**：

```json
{
  "limit": 20,
  "hard_filters": [
    {"field": "followers", "operator": "lt", "value": 1500}
  ],
  "semantic_filters": [
    {"field": "experienced_projects", "operator": "any_of", "values": ["光子嫩肤", "水光针", "皮秒"]},
    {"field": "skin_concerns", "operator": "any_of", "values": ["晒斑", "雀斑", "黄褐斑", "产后斑"]}
  ],
  "preferences": [
    {"field": "activity", "operator": "high"}
  ]
}
```

### 8.5 FR-05 实时搜索与候选获取

**用户故事**：作为媒介专员，我希望系统基于确认后的规则实时搜索小红书，避免只分析预置静态名单。

**功能规则**：

- 只有小红书处于已连接状态才能发起检索。
- 检索为异步任务，页面展示任务阶段和已获取候选数量。
- 系统使用产品相关关键词、语义扩展词和分页策略获取初始候选。
- 系统先执行硬条件筛选，再调用 AI 做语义分析。
- 后续检索必须排除当前项目所有历史任务已经发现或筛查过的达人；同一条件再次检索时复用持久化游标。
- 每个检索任务目标是返回 20 名不重复有效候选人；不得设置固定 100 人候选池，合格人数不足时由系统自动续批和继续分页，直至达到目标、数据源耗尽、供应商真实限流或触发整任务安全调用预算。
- 已采用、已弃用、待处理以及此前筛选不通过的达人均按项目永久排除，不因修改检索条件而重复返回。
- 页面不提供独立“继续检索”按钮；本批结束后，用户再次点击顶部“开始检索”即可从已保存游标发起下一批。
- 因数据不足、频控或上游异常无法达到批次目标时，必须展示实际数量和原因。
- 用户可取消正在运行的任务；已保存的阶段结果可以保留。

**任务状态**：

- 等待中
- 获取候选中
- 数据分析中
- 已完成
- 部分完成
- 已取消
- 连接失效
- 平台频控
- 失败

**验收标准**：

- 检索结果不是预置静态数据冒充的实时结果。
- 结果不足 20 人时显示明确原因；数据源未耗尽时允许再次点击顶部“开始检索”。
- 同一项目的多次检索不重复返回任何历史任务已经发现或筛查过的达人。
- 相同条件再次检索沿用上次游标，不重复分析项目历史笔记和达人。

### 8.6 FR-06 达人分析、评分与待确认

**分析数据**：

- 小红书用户 ID、昵称、头像和主页链接。
- 粉丝数、获赞与收藏等可合法取得的基础数据。
- 最近发布频次、最近活跃时间和公开互动数据。
- 历史图文或视频中可取得的公开内容。
- 项目经历、皮肤困扰等语义判断。

**处理规则**：

- 粉丝量、日期、去重等确定性条件由代码处理。
- 内容语义、项目经历和困扰识别由 AI 处理。
- 每个语义结论必须包含证据摘要、来源笔记和置信度。
- 无法确认的条件保留达人，并标记“待人工确认”，不得直接排除。
- 匹配分只用于排序，不表示客观质量或商业价值。

**活跃度临时口径（待 Eval 校准）**：

首版可综合最近 30 天发文数、距最近发文天数和公开互动表现计算 0–100 分。具体权重属于待验证算法配置，不在 PRD 中锁死。

**达人匹配状态**：

- 符合
- 部分符合
- 待人工确认
- 不符合

### 8.7 FR-07 候选达人列表

**列表字段**：

- 头像、昵称、小红书用户 ID。
- 粉丝数、获赞与收藏数等可用公开数据。
- 活跃度分及构成说明。
- 匹配分。
- 匹配标签和不确定标签。
- 匹配理由和证据笔记。
- 当前业务状态。
- 自定义标签或分组。
- 主页链接。
- 获取时间。

**功能规则**：

- 支持按状态、粉丝数、匹配度、活跃度、标签筛选。
- 支持按匹配度、粉丝数、活跃度排序。
- 点击主页链接在新窗口打开小红书主页。
- 用户可单个或批量选入、弃用。
- AI 不自动代替用户完成最终选入。

### 8.8 FR-08 状态、分组与去重

**达人业务状态**：

- 待处理：默认状态。
- 选入：用户决定进入后续合作名单。
- 弃用：用户暂不采用。

**状态转换**：

```text
待处理 ↔ 选入
待处理 ↔ 弃用
选入 ↔ 弃用
```

**唯一性规则**：

- 达人全局标识：`xiaohongshu_user_id`。
- 项目内唯一键：`project_id + xiaohongshu_user_id`。
- 自定义标签和分组不参与唯一性判断。

**功能规则**：

- 用户可创建、重命名自定义分组。
- 达人可属于一个主分组，并拥有多个自定义标签；MVP 若实现时间不足，优先实现多标签，主分组降为 P1。
- 状态转换需要记录操作者和时间。
- 后续检索遇到同一项目已有达人时不作为新结果返回，可在检索摘要中显示“已排除重复 N 人”。

### 8.9 FR-09 Excel 导出

**功能规则**：

- 用户可导出当前项目的全部达人或当前筛选结果。
- 可选择导出待处理、选入、弃用状态。
- 导出字段与列表主要字段一致，并包含主页链接、匹配理由、标签、状态和获取时间。
- 文件名格式：`{项目名称}_{状态或全部}_{YYYYMMDD_HHmm}.xlsx`。
- 导出仅包含当前用户当前项目的数据。

### 8.10 FR-10 公共广告法知识库

**定位**：为所有用户提供只读的广告法基础审核依据。

**知识内容**：

- 现行有效《中华人民共和国广告法》官方原文。
- 条款编号、效力状态、生效或修订日期、官方来源链接。
- 从条文整理的原子审核规则。
- 原子规则到法律条文的引用关系。

**功能规则**：

- 所有用户共享读取，不能编辑、删除或覆盖。
- 法律版本更新必须保留版本号和更新时间。
- 审核结果引用公共规则时必须返回条款号和来源。
- 系统不能仅依据向量相似度直接判定违法，必须由结构化规则和模型共同生成“风险提示”。

### 8.11 FR-11 私有知识库

**用户故事**：作为媒介专员，我希望上传公司的审核标准、平台规则或行业规范，使审核符合自己的业务要求。

**功能规则**：

- 用户可创建多个私有知识库。
- 每个知识库包含名称、说明、文档数量、更新时间和状态。
- 支持 PDF、DOCX、TXT、Markdown。
- 单个文件大小和页数限制由技术方案根据托管资源确定，界面必须明确展示。
- 文档处理状态包括：等待处理、解析中、可用、解析失败。
- 用户可查看文档、重新处理和删除文档。
- 私有知识库、原始文件、切片和向量数据必须按 `user_id` 隔离。
- 用户可在每次审核时选择一个或多个私有知识库。
- 不同私有规则冲突时，系统分别展示冲突来源，不得静默选择其中一条。
- 私有规则可以比广告法更严格，但不能覆盖或降低法律要求。

### 8.12 FR-12 新建图文审核

**输入字段**：

- 任务名称：选填，默认使用标题和时间生成。
- 图文标题：选填。
- 正文：必填，或由上传材料解析得到。
- 图片：至少 1 张；支持常见图片格式。
- 审核要求：选填。
- 推广脚本：选填。
- 私有知识库：选填，可多选。

**MVP 审核范围**：

- 标题文本。
- 正文文本。
- 图片 OCR 提取的文字。
- 用户输入的额外要求和脚本。
- 公共广告法知识库。
- 用户本次选择的私有知识库。

**不审核**：

- 图片人物、场景、动作、商标和其他非文字视觉内容。
- 视频、音频和口播。
- 未被 OCR 正确识别的图片文字。

### 8.13 FR-13 审核结果

**总体结论**：

- 通过：在本次覆盖规则范围内未发现风险。
- 警告：存在需要修改或人工确认的中低风险问题。
- 不通过：存在明确高风险项。
- 待人工/法务确认：上下文、规则冲突或事实不足，系统无法可靠判断。

**每条风险项包含**：

- 风险等级：高、中、低。
- 风险分类。
- 命中内容。
- 内容位置：标题、正文段落、图片序号及 OCR 文本区域。
- 风险说明。
- 规则来源：公共广告法或具体私有知识库/文档。
- 条款编号或文档章节。
- 来源更新时间。
- 修改建议。
- 置信度或待确认原因。

**规则优先级**：

1. 公共广告法是不可覆盖的基础层。
2. 用户私有规则独立叠加。
3. 私有规则冲突时同时展示。
4. 无明确依据时不得输出确定性违法结论。

**覆盖范围提示**：

当用户未选择私有知识库时，结果页必须显著显示：

> 本次仅完成《中华人民共和国广告法》基础检查，未覆盖小红书平台、行业及企业内部规则；结果不代表完整合规结论。

所有结果页固定显示：

> 本结果由 AI 提供辅助审核，不构成法律意见，发布前仍需人工复核。

### 8.14 FR-14 审核记录

**功能规则**：

- 保存任务输入、OCR 结果、选择的知识库版本、审核结果和创建时间。
- 用户可查看历史记录。
- 审核结果必须绑定当时使用的规则版本，规则更新后不得自动改写历史结论。
- 用户可基于历史任务重新审核；重新审核生成新版本记录。

## 9. AI 与 RAG 处理设计

### 9.1 模型选择

首版开发和运行模型暂定 `gpt-5.6-sol`，通过 OpenAI Responses API 调用。该选择属于产品决策，但仍需在本地 Eval 中验证效果、延迟和成本；若无法满足预算，可以在保持接口兼容的前提下评估更低成本模型。

### 9.2 成本控制原则

- 先用确定性代码执行粉丝量、日期、状态和去重等规则。
- 只将需要语义判断的候选内容发送给模型。
- 达人笔记先进行去噪、截断和摘要，避免无边界输入。
- 使用结构化输出，减少重复生成。
- 对相同内容和规则版本进行安全缓存。
- 本地 Eval 记录 token、费用、延迟；线上不开发用户可见的用量页面。

### 9.3 RAG 流程

```text
上传规则文档
→ 文件解析
→ 按条款/章节切分
→ 保存来源、版本、页码/章节元数据
→ 生成向量索引
→ 审核时按内容召回相关规则
→ 公共广告法与私有规则分别召回
→ 模型生成结构化风险项
→ 风险项必须带来源引用
```

### 9.4 审核输出 Schema（建议）

```json
{
  "overall_status": "warning",
  "coverage": {
    "public_law": true,
    "private_knowledge_bases": ["公司医美审核规范"]
  },
  "risks": [
    {
      "severity": "high",
      "category": "功效保证",
      "matched_text": "一次就能彻底解决",
      "location": {"type": "body", "index": 2},
      "reason": "存在对效果作保证的风险",
      "source_type": "public_law",
      "source_title": "中华人民共和国广告法",
      "source_section": "第十六条",
      "suggestion": "删除确定性保证，改为与已获批准材料一致的客观描述",
      "confidence": 0.91,
      "needs_human_review": false
    }
  ],
  "limitations": ["未识别图片非文字视觉内容"]
}
```

模型的 `confidence` 是系统内部估计，不代表法律事实概率。阈值由本地 Eval 校准。

## 11. 异常状态与降级规则

| 场景 | 系统行为 |
|---|---|
| 小红书未连接 | 禁止检索，跳转扫码连接 |
| 会话在检索中失效 | 暂停任务，保留进度，提示重新扫码 |
| 平台频控或账号限制 | 停止继续请求，显示部分结果和风险提示 |
| 单批达人不足 20 人 | 返回实际数量并解释原因；数据源仍可继续时允许从持久化游标续检，不伪造补足 |
| 某条件无法判断 | 保留达人，标记待人工确认 |
| AI 请求失败 | 有界重试；仍失败则记录失败并允许重新执行 |
| 私有文档解析失败 | 文档标记失败，不进入可选规则库 |
| OCR 低置信度 | 标记对应图片文字需人工核验 |
| 多条私有规则冲突 | 分别展示冲突来源，结论设为待确认 |
| 没有选择私有规则 | 仅执行广告法基础审核并显示覆盖提示 |
| 规则无匹配依据 | 不输出确定性违法判断，进入待人工确认 |
| 导出失败 | 保留当前筛选状态，允许重试 |

## 12. 非功能需求

### 12.1 安全与隐私

- API Key 只存储在服务器端环境变量或密钥服务中，不进入浏览器代码。
- 小红书会话凭证加密保存，日志中不得记录完整凭证。
- 用户上传文档、审核内容和达人项目数据按 `user_id` 隔离。
- 文件访问使用短期签名地址或后端鉴权下载。
- 日志不得记录不必要的完整图文、会话和个人敏感信息。
- 支持用户断开小红书连接并使会话失效。

### 12.2 性能

- 普通页面首屏目标在 3 秒内可交互，具体取决于部署网络。
- 长耗时检索和审核采用异步任务并展示进度。
- 内容审核目标响应时间在真实数据验证后确定，MVP 不作商用 SLA 承诺。

### 12.3 可追溯性

- 每次检索保存原始条件和解析条件。
- 每个达人语义判断保存证据来源和获取时间。
- 每次审核保存使用的规则版本和来源。
- 结果修改或重新审核不能覆盖历史版本。

### 12.4 可观测性

- 线上仅保留运行必需的错误日志、任务状态和故障定位信息。
- 不在用户系统中展示 Eval、token、费用或模型内部推理。
- API 成本通过 OpenAI Platform 后台管理。

## 13. 本地 Eval 方案

本节属于研发验收，不部署到线上产品。

### 13.1 达人筛选 Eval

**数据建议**：不少于 100 名候选达人，由人工依据同一筛选条件标注符合、部分符合、待确认或不符合，并记录理由。

**指标**：

- 人工准确率：系统返回候选中，经人工确认符合目标要求的比例。
- 条件级准确率：粉丝量、项目经历、皮肤困扰、活跃度分别统计。
- 待确认质量：系统标记待确认的案例中，是否确实缺少充分证据。
- 任务效率：完成 20 名可用候选的时间。

### 13.2 内容审核 Eval

**数据建议**：不少于 60 条图文案例，其中至少 30 条含明确风险；每条标注风险原文、风险类别、规则依据和期望结论。

**指标**：

- 风险召回率：标注风险中被系统识别的比例。
- 风险精确率：系统提示风险中经人工确认有效的比例。
- 引用正确率：风险依据是否引用正确条款或私有规则。
- 定位准确率：是否定位到正确标题、正文或图片 OCR 文本。
- 修改建议可用率：人工判断建议是否可执行且未改变原意。

### 13.3 Eval 约束

- Eval 只能使用脱敏数据。
- 测试集与提示词开发集分离，避免只针对固定案例优化。
- 记录模型版本、提示词版本、规则版本、费用和运行时间。
- 未达到指标时不得将结果包装为成功。

## 18. 官方法规基线

公共知识库首版只使用现行《中华人民共和国广告法》，并以官方现行文本为准。产品设计时参考但不默认内置其他行业规则：

- [《中华人民共和国广告法》现行文本（国家法律法规数据库）](https://flk.npc.gov.cn/detail?fileId=&id=ff8081817ab231eb017abd6bd860052d&title=%E4%B8%AD%E5%8D%8E%E4%BA%BA%E6%B0%91%E5%85%B1%E5%92%8C%E5%9B%BD%E5%B9%BF%E5%91%8A%E6%B3%95&type=)
- [《互联网广告管理办法》（市场监管总局）](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/fgs/art/2023/art_d93a579afd45413e8576e4623fab348f.html)
- [《医疗广告管理办法》（市场监管总局）](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/ggjgs/art/2023/art_6584dc1c94c2408db7c73f0b5e3d225a.html)
- [《医疗美容广告执法指南》（市场监管总局）](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/ggjgs/art/2023/art_d1b46dbc27214abcace53a0ec539f7bb.html)

后三项仅作为产品边界研究依据，不进入公共 RAG；用户如需使用，应自行上传至私有知识库并维护版本。
