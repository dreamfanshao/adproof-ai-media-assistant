## 3. 各区域边界

### 3.1 输入素材

输入素材回答“依据什么开展工作”。新增素材必须先登记来源、用途、版本和限制。账号密码、Cookie、Token、验证码和 API Key 禁止入库。

### 3.2 任务

每个任务使用统一结构：

```text
02-任务/01-current/Txx-任务名称/
├── 任务说明.md
├── 工作产出/
└── 验收证据/
```

`01-current/` 最多存在一个任务包。未启动任务进入 `02-planned/`，完成并确认后整体移入 `99-done/`。

### 3.3 交付物

每类交付物采用 `01-current/` 和 `99-history/`。版本升级时先将旧版移入 history，再将已确认新版放入 current。未获确认的草稿留在任务包中。

### 3.4 分析

`04-分析/` 保存可复用的调研和判断，不与正式交付物混放，同样采用 current/history 生命周期。

### 3.5 工作台、决策与日志

工作台只维护当前状态；决策账本只追加，不删除被替代决定；日志记录实际完成事项，不替代任务说明和交付物。

## 7. 禁止出现的问题

- 不把输入、分析或草稿放入交付物 current。
- 不保留多个含义不明的“最新版”。
- 不在工作区根目录散落无主文件。
- 不存储账号密码、Cookie、Token、验证码、证书或 API Key。
- 不用静态数据冒充实时小红书结果。
- 不把 AI 审核结果表述为法律意见或监管认定。
- 不把本地 Eval、标注集、费用与模型日志部署为用户功能。
