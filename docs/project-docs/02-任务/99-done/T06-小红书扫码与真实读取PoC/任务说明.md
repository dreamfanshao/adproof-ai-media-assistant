## 任务目标

验证“小红书二维码获取 → 用户扫码 → 登录状态识别 → 会话可用 → 搜索结果页读取 → 单达人主页读取”的真实技术链路，并给出可继续、需调整或不可行的证据化结论。

## 本期范围

1. 建立独立 Node.js Worker 与 Playwright Chromium 运行骨架。
2. 实现小红书连接创建、状态查询和断开接口。
3. 获取真实二维码并在前端连接页展示短时二维码。
   - 二维码仅在用户首次开始检索且无有效会话，或会话过期/失效时展示；登录媒介助手本身不触发扫码。
   - 扫码成功后返回并继续用户刚才发起的检索；有效会话内后续检索不重复扫码。
4. 由用户本人扫码授权，识别扫码中、成功、过期、受限和失败状态。
5. 会话成功后尝试读取一页真实搜索结果。
6. 尝试读取一个真实达人主页的 MVP 必需字段。
7. 保存脱敏日志、状态事件、字段覆盖和失败分类，不保存二维码或可复用账号凭据到文档。

## 验证边界

- 不绕过验证码、设备校验、频控或平台风控。
- 不声称获得小红书官方 API 授权。
- 只处理完成 PoC 所需的最小公开页面数据，限制访问频率。
- 不以静态数据、旧数据或 Demo 数据冒充实时链路成功。
- Cookie、Token、Storage State 必须加密后才能持久化，浏览器和文档不得暴露。
- PoC 允许得出失败或受限结论。

## 验收标准

- 二维码来自本次真实浏览器会话，并可被用户扫码。
- 状态机能区分至少 `qr_pending`、`qr_scanned`、`connected`、`expired`、`restricted`、`failed`。
- 成功时能证明会话仍可用，并读取真实搜索页和单达人主页最小字段。
- 失败时能给出发生阶段、页面状态、错误分类和可复现条件。
- 任何证据中不包含可复用 Cookie、Token、二维码、密码或完整账号标识。
- 结论明确说明是否可以进入达人检索主链路开发。
