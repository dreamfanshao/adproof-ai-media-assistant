## 任务目标

把现有演示登录替换为真实 Supabase 邮箱密码认证，建立前端受保护路由和 Fastify API 鉴权基础，并让 `/health`、`GET /me`、`PATCH /me` 符合已确认契约。

## 本期范围

1. 接入 Supabase 邮箱密码注册、登录、Session 恢复与退出。
2. 未登录用户不能进入业务路由，已登录用户不能返回登录页。
3. Fastify 提供 `/api/v1/health`、`GET /api/v1/me`、`PATCH /api/v1/me`。
4. Fastify 使用 Supabase `getClaims()` 验证 Bearer Token，并只从 Token `sub` 获取 `user_id`。
5. 普通资料访问使用用户 Token 调用 Supabase，保持 RLS 生效。
6. 配置严格 CORS、安全响应头、请求体上限、按 IP 基础限流和统一错误结构。
7. 增加接口自动测试、类型检查和生产构建验证。

## 不在本任务执行

- 不使用或下发 Supabase service role key。
- 不实现小红书扫码、浏览器会话或 Cookie 保存。
- 不实现达人搜索、RAG、OCR 或 AI 审核 Workflow。
- 不部署生产环境。

## 验收标准

- 新用户可通过邮箱密码注册，已有用户可登录和退出。
- 刷新页面后 Supabase Session 可恢复。
- 未登录访问业务 URL 会跳转登录页。
- `/health` 无需 Token；`/me` 缺少或携带无效 Token 时返回 401。
- `/me` 的身份来自已验证 Token，前端无法通过请求体伪造 `user_id`。
- 用户资料读取和更新受现有 RLS 约束。
- 自动测试、TypeScript 检查和生产构建通过。
- `.env`、Publishable Key 以外的密钥、Token 和测试密码不进入 Git 或项目文档。
