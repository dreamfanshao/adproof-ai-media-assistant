## 任务目标

实现 MVP 第二主链路：私有知识库入库（文档解析/切块/状态机）→ 广告法公共库 → 图文内容合规辅助审核（上传图文 → 文字抽取 → 规则检索 → 风险分析 → 结构化结果 → 人工复核提示），并把 T01 前端知识库/审核页面从 demo 切换到真实 API。

## 本期范围（分阶段推进）

### Phase 1｜知识库入库（Workflow C）

1. Fastify 路由：`knowledge-bases`（列表/创建/详情/更新/删除）、`document-upload-intents`（签名上传）、`documents`（列表/提交/详情/删除）——按 API 契约 v1。
2. 签名上传：Supabase Storage 预签名 URL，MIME/大小（≤20MB）/校验和校验。
3. Worker `knowledge_ingest` job：解析（PDF/Word/TXT/MD）→ 清理页眉页脚/重复空白 → 按标题/条款切块（法规按条、私有 400–800 字 + 10% 重叠）→ 生成 source_locator/checksum/版本 → 写入 knowledge_chunks → 可检索性抽样检查 → 状态流转（uploaded→parsing→chunking→validating→ready / needs_attention / failed）。
4. Embedding：Q003 延后——不生成向量、不建 ANN 索引；MVP 用全文/关键词检索，chunk 保留 embedding 空列待补。

### Phase 2｜广告法公共库

5. 内置《中华人民共和国广告法》文本入库（公共知识库，D004）；文档按"条"切分，保存法规名称/版本/条款号。
6. 知识库选择与覆盖提示：公共库恒可选；私有库 `selectable` 规则（≥1 份 ready 文档）、`needs_attention` 时提示覆盖不完整。

### Phase 3｜图文内容合规审核（Workflow D）

7. 审核任务：`POST /audit-tasks`（标题/正文/审核要求/知识库选择）+ 图片上传（签名 URL，≤9 张，JPG/PNG ≤10MB）。
8. 文字抽取：首版**规则模式匹配 v1**（广告法绝对化用语/极限词等规则库命中标题/正文 → 风险发现），图片文字抽取与 LLM 语义分析留接口（需 `OPENAI_API_KEY` 时启用；未配置则图片进入待人工复核）。
9. 规则检索：公共广告法 + 用户勾选私有知识库（关键词/分块检索）；权限与版本校验。
10. 风险输出：风险项（等级 low/medium/high/needs_confirmation、类别、原文定位、依据条款、修改建议、置信度）；`overall_risk` 由代码合成（§15.2：模型不返回最终结论）；保存知识库快照（版本化，历史结果不随知识库更新而变）。
11. 审核结果页 + 历史页：从 demo 切真实 API；固定展示"AI 辅助审核，不构成法律意见，需人工复核"。

### Phase 4｜前端接入与验收

12. 知识库页：列表/上传/状态（处理中/就绪/失败）/选择开关。
13. 新建审核/审核结果/审核历史页真实接入；人工复核入口（needs_confirmation）。
14. 验收证据与归档（同 T07 流程）。

## 验证边界

- 本地 Eval 与用量记录只本地运行（D005），不部署；AI 审核结果不得表述为法律意见或监管认定。
- 不绕过文件类型/大小/校验和校验；解析失败转 `needs_attention`，不静默生成空库。
- 凭据只经环境变量注入；文档正文与审核结果按用户隔离（RLS 已建）。
- 图片 OCR/LLM 语义分析：无 `OPENAI_API_KEY` 时以规则模式匹配 v1 + 人工复核兜底；LLM 启用后须经本地 Eval 校准再放宽。

## 验收标准

- 上传 PDF/Word/TXT/MD → 状态到 ready，chunk 落库且可检索；失败/部分失败有明确状态与原因。
- 广告法公共库可检索；私有知识库选择与覆盖提示正确。
- 上传标题/正文 → 审核任务 → 风险项（定位/依据/建议）落库 → 结果页展示 + 人工复核提示；历史结果不随知识库更新改变。
- 任意界面不出现"已通过/不通过"的法律结论式表述（用 风险等级 + 依据 + 建议）。
