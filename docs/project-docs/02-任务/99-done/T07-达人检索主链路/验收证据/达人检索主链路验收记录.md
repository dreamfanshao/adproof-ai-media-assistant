### Phase 2｜语义匹配（启发式 + 确定性合成）

- `match_score` 由代码合成（语义 50% + 活跃 25% + 证据 25%），模型不返回排序分（技术方案 §13.3）。
- E2E 实测：真实达人"白日做梦师"命中"光子嫩肤/医美" → `matchScore 65` > 未命中者 40；活跃度分、`evidence_summary`、`analysis_json`、`creator_evidence`（ai_analysis）全部落库；search_tasks 记录 `model_version=heuristic-v1`/`prompt_version=creator-semantic-match.v1`。
- LLM 判定路径（OpenAI-compatible，需 `OPENAI_API_KEY`）已留接口，未启用。

### Phase 3｜API 路由 + SSE + 前端接入

- 集成测试（HTTP→DB→Worker→SSE 全链路，exit 0）：建项目 200 → `search-rules:parse` 200（"粉丝<1500、活跃度较高、做过光子嫩肤或有雀斑困扰" → 硬条件 followers<1500 + 语义 c1:experience:光子嫩肤 c2:concern:雀斑 + 活跃度排序 + limit 50 + ambiguities 空）→ 建任务 queued → 执行器 completed（persisted 3, heuristic-v1）→ 达人列表按 match_score 降序 → PATCH selected → SSE 200 事件流。
- 前端：找达人页真实全流程（自动建默认项目 → 解析条件展示 → 建任务 → 2s 轮询进度 → 真实候选表格（头像/主页链接）→ 选入/弃用/恢复 PATCH → 重复数展示）；挂载加载历史候选。
- 修复记录：`search_tasks_one_active_per_user_idx` 冲突 → createSearchTask 自动取消既有进行中任务；Worker 守护进程 `task_id` 崩溃 → 改用 `payload.search_task_id`；执行器检查 `cancel_requested`。
