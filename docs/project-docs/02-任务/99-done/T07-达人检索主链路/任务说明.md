## 任务目标

基于已验证的小红书会话，实现真实达人检索主链路：自然语言条件解析 → 异步检索任务 → 真实搜索页收集 → 达人主页字段映射 → 硬条件过滤 + AI 语义匹配 → 候选列表落库 → 前端真实接入（选入/弃用/分组）→ 项目内去重 → Excel 导出。

## 本期范围（分阶段推进）

### Phase 1｜真实检索读取与字段映射（Worker）

1. 独立 Worker 检索执行器：从 `private.jobs`（type=creator_search）领取任务（Job fencing 租约），校验小红书会话。
2. 搜索页收集：`/search_result?keyword=…&source=web_explore_feed` 读取达人卡片列表，提取平台达人 ID、昵称、头像、主页链接；分页到目标数量或自然耗尽。
3. 达人主页字段映射：粉丝数、获赞与收藏、笔记数、主页简介等 MVP 必需字段（脱敏证据 + 失败分类）。
4. 更新 `search_tasks` 状态/进度（collecting → hard_filtering → analyzing_creators → persisting_creators）与 `private.job_events`（SSE 进度事件）。

### Phase 2｜两步检索流水线

5. 硬条件过滤：按 `confirmed_rule`（粉丝数上限等结构化条件）过滤，统计不足原因（partial_reason）。
6. AI 语义匹配：对剩余候选做内容/笔记相关度分析，输出 match_score 与 evidence_summary、analysis_json。
7. 排序与数量：目标 50 人；不足时如实返回实际数量与原因，不伪造补足。

### Phase 3｜API 路由与前端接入

8. Fastify 路由：`search-rules:parse`、`search-tasks` CRUD/取消、`creators` 列表/更新/批量、`export.xlsx`、`/tasks/{id}/events` SSE——按 API 契约 v1 实现（数据库/RLS 已就绪）。
9. 前端找达人页从 demo 数据切换到真实 API：解析条件 → 创建检索 → 轮询/SSE 进度 → 候选表格真实数据 → 选入/弃用/分组调用 API。

### Phase 4｜去重与导出

10. 项目内去重：后续检索排除本项目已保存达人（duplicate_count + "已排除重复 N 人"）。
11. Excel 导出（FR-09）：待处理/选入/弃用状态、主页链接、匹配理由、标签、状态、获取时间，仅当前用户当前项目数据。

## 验证边界

- 不绕过验证码、设备校验、频控或平台风控；限制访问频率，失败分类记录。
- 不声称获得小红书官方 API 授权。
- 检索结果必须是实时真实数据，禁止用静态样本冒充；不足 50 人时说明原因。
- Cookie、Token、Storage State 仅以 AES-256-GCM 密文落库；证据与日志不输出凭据、完整账号标识。
- 频控阈值、批量翻页、长时间稳定性、并发为已知边界，纳入失败分类与重试设计，不作为 MVP 承诺。

## 验收标准

- 用户点击"开始检索"后：条件解析 → 异步任务 → 真实候选列表（实时数据）返回，进度可见。
- 达人主页 MVP 字段可读取，字段缺失有 warning/evidence 记录，data_completeness 区分 complete/partial。
- 硬条件过滤与语义匹配生效，match_score/evidence_summary 落库并展示匹配理由。
- 项目内去重生效；导出 Excel 与列表字段一致。
- 任意证据不含可复用 Cookie、Token、二维码、密码或完整账号标识；不触发自动绕过风控。
