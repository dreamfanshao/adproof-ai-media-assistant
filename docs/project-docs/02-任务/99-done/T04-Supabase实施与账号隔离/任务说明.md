## 任务目标

把已确认的数据库、RLS、Storage 和 Worker 租约方案落到可重复执行的 Supabase 测试环境，并为前端接入真实邮箱密码登录建立可信数据基础。

## 本期范围

1. 初始化并固定 Supabase CLI 项目结构。
2. 将 001–006 Migration 接入 `supabase/migrations/`。
3. 在空库执行 Migration、seed 和数据库 lint。
4. 创建两个一次性测试账号，运行 RLS/Storage 隔离测试。
5. 运行 Job 租约过期、重领和旧 Worker 写入拒绝测试。
6. 生成数据库 TypeScript 类型，为前端 Auth 和 Fastify API 使用。

## 不在本任务执行

- 不接入真实小红书账号或保存 Cookie/Token。
- 不导入正式广告法正文。
- 不部署生产环境。
- 不实现达人搜索、OCR、RAG 或 AI 审核 Workflow。

## 验收标准

- `supabase db reset` 能从空库顺序执行全部 Migration。
- 数据库 lint 无 error。
- 用户 A/B 不能读取或修改对方私有数据及 Storage 对象。
- 浏览器角色不能访问 `private.*` 或 `platform_sessions`。
- 旧 Worker 使用过期 `lease_version` 写入时被数据库拒绝。
- 生成的数据库类型可通过 TypeScript 编译。
